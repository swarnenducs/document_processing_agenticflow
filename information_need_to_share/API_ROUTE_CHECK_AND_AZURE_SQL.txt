2. Azure SQL config — YES, it is present
----------------------------------------
This is env-only. No code change is required to switch SQLite vs Azure SQL.

A) Code
  ipp_agentic_api/src/ip_api/core/settings.py
    AZURE_SQL_SERVER, AZURE_SQL_USER, AZURE_SQL_PASSWORD, AZURE_SQL_DATABASE
    AZURE_SQL_DIALECT (default pyodbc), AZURE_SQL_ODBC_DRIVER
    uses_azure_sql = SQLALCHEMY_DATABASE_URL set, OR (SERVER and PASSWORD both set)

  ipp_agentic_api/src/ip_api/storage/db.py
    build_database_url(): explicit URL > Azure SQL parts > SQLite file
    mssql+pyodbc (ODBC Driver 18) or mssql+pymssql
    ensure_schema() creates tables + Azure SQL NVARCHAR migrations / overview views

  Same AZURE_SQL_* pattern in:
    document-processing-mcp, voice_enable_mcp, central-agentic-flow

B) Azure Web App settings JSON (placeholders, Key Vault for password)
  Present in:
    ipp_agentic_api/config/azure-webapp.settings.json
    document-processing-mcp/config/azure-webapp.settings.json
    voice_enable_mcp/config/azure-webapp.settings.json
    central-agentic-flow/config/azure-webapp.settings.json
  Keys: AZURE_SQL_SERVER, AZURE_SQL_USER=adminsql, AZURE_SQL_DATABASE=ipp-app-db,
        AZURE_SQL_DIALECT=pyodbc, AZURE_SQL_ODBC_DRIVER=ODBC Driver 18 for SQL Server,
        AZURE_SQL_PASSWORD=@Microsoft.KeyVault(.../secrets/azure-sql-password/)
  UI/config/azure-webapp.settings.json has NO Azure SQL keys (correct — UI has no DB).

C) Local .env (repo root) — present, but password is empty
  AZURE_SQL_SERVER          set  (hostname ends with .database.windows.net)
  AZURE_SQL_USER            set
  AZURE_SQL_DATABASE        set
  AZURE_SQL_DIALECT         set
  AZURE_SQL_ODBC_DRIVER     set
  AZURE_KEY_VAULT_NAME      set
  AZURE_KEY_VAULT_URL       set
  AZURE_SQL_PASSWORD_SECRET_NAME  set
  AZURE_SQL_PASSWORD        EMPTY (meant to be filled from Key Vault)
  IPP_USE_AZURE_SQL         1
  FILE_STORAGE_BACKEND      azure_blob

  Because the password string is empty, Settings.uses_azure_sql is false until
  scripts/load_sql_password_from_keyvault.py fills AZURE_SQL_PASSWORD.

D) Local launcher behaviour
  python run_all_components.py defaults to SQLite unless --azure-sql or IPP_USE_AZURE_SQL=1.
  This repo's .env has IPP_USE_AZURE_SQL=1, so a full local start WILL try Azure SQL
  (and Key Vault for the password). Azure Web Apps do not use that launcher; they
  use the JSON settings + Key Vault reference.

E) How the API reports it
  GET /api/v1/health
    azure_sql_server / azure_sql_database   populated only when MSSQL is active
    azure_sql_available                     true/false after SELECT 1, or null on SQLite


3. How to run the API locally for the UI team
---------------------------------------------
SQLite (recommended on a laptop):
  python run_all_components.py
  (if IPP_USE_AZURE_SQL=1 in .env, pass nothing extra only if you really want Azure SQL)
  To force SQLite even with that flag: unset IPP_USE_AZURE_SQL, do not pass --azure-sql.

API only:
  python -m ip_api.run_app --api-only --no-mcp --no-maf

Then open http://127.0.0.1:8000/docs
